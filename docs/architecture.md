# Архитектура AniTier

Краткая карта модулей, порядка загрузки, границ слоёв и хранилищ. Документ описывает текущее устройство репозитория; список загружаемых модулей должен совпадать с `tests/shell.test.js` (`SHARED`).

## Оболочки

- **Десктоп/веб:** `index.html` + `styles.css` + общие скрипты. Открывается локально, через `serve.ps1` или GitHub Pages.
- **Мобильная PWA:** `mobile/index.html` + `mobile/mobile.css` + `mobile/mobile.js` + общие скрипты из `../`; кеш оболочки — `mobile/sw.js`, манифест — `mobile/manifest.webmanifest`, иконки — `mobile/icons/`.
- **Автономный файл:** `AniTier-phone.html` собирается `build-phone.ps1` (скрипты и стили вшиваются).
- **Android APK:** WebView-оболочка в `android/`; `android/build-apk.ps1` собирает `AniTier.apk` после обновления `AniTier-phone.html`/assets.

Во всех оболочках используется одна и та же бизнес-логика и общий набор модулей.

## Порядок загрузки скриптов

Порядок зафиксирован в `index.html`, `mobile/index.html`, `build-phone.ps1`, `mobile/sw.js` и проверяется `tests/shell.test.js` / `tests/split.test.js`.

Общие скрипты (`SHARED`), в порядке загрузки:

1. Данные: `tags.js`, `titles-ru-anilist.js`, `titles-ru.js`, `changelog.js`
2. Ядро: `core.js`
3. Состояние и API: `app-store.js`, `app-api.js`
4. Рендер: `app-render-cards.js`, `app-render-lists.js`, `app-render-screens.js`, `app-render-modals.js`, `app-render-exchange.js`, `app-render-png.js`, `app-render-settings.js`, `app-render-command.js`
5. Контроллеры: `app-ctrl-catalog.js`, `app-ctrl-notifications.js`, `app-ctrl-upcoming.js`, `app-ctrl-backup.js`, `app-ctrl-posters.js`, `app-ctrl-moments.js`, `app-ctrl-settings.js`, `app-ctrl-diagnostics.js`, `app-ctrl-gestures.js`, `app-ctrl-safety.js`
6. Запуск: `app.js`

Только мобильная оболочка дополнительно подключает `mobile.js` после общих скриптов.

## Границы слоёв

- `core.js` (`window.AniTierCore`) — чистые функции без DOM, `fetch`, `localStorage` и глобального состояния приложения: фильтры, переменные запросов, склейка/пагинация, обмен тир-листами, разбор импортов, PNG-раскладка, статистика, версия/релизы, утилиты.
- Файлы данных (`tags.js`, `titles-ru*.js`, `changelog.js`) — только данные, без логики рендера.
- `app-store.js` — состояние, `localStorage`, доступ к IndexedDB, списки, прогресс, свои карточки, моменты, настройки, резервные копии/снапшоты. Экспортирует API в `window.AniTier`. Сетевых запросов не делает.
- `app-api.js` — AniList GraphQL, Kitsu, кэш ответов, переводы, метаданные TikTok, Google Drive, демо-данные. Без прямого рендера DOM; экспорт в `window.AniTier`.
- `app-render-*.js` — отрисовка карточек, списков/тиров, экранов, модалок, обмена, PNG, настроек/статистики, палитры команд. Без сетевых запросов; DOM/canvas допустимы там, где это задача модуля (например, PNG). Перекрёстные вызовы — через `App.*`.
- `app-ctrl-*.js` — обработчики действий, загрузка/обновление данных, навигация по экранам, жесты, резервные копии, постеры, моменты, настройки, диагностика. Сеть — через `app-api.js`/`App.*`, рендер — через `app-render-*`/`App.*`.
- `app.js` — контроллер: связывает события, drag & drop/жесты (через модули), реестр действий, инициализация и запуск. Бизнес-логику по возможности держит в `core.js`, `app-store.js` или профильных модулях.

Общий паттерн модулей: IIFE `(function (App) { 'use strict'; const C = window.AniTierCore; ... Object.assign(App, { ... }); })(window.AniTier)`. Перекрёстные вызовы — ленивые (`(...a) => App.fn(...a)`), чтобы не зависеть от порядка определения внутри слоя.

## Потоки данных

1. **Каталог/поиск:** контроллер запрашивает данные через `app-api.js` (AniList — основной источник; Kitsu — второй источник текстового поиска). Ответы нормализуются/склеиваются, кешируются; рендер показывает выдачу, фильтры и состояния загрузки/ошибки. При недоступности источников используется демо-режим.
2. **Списки и прогресс:** действия пользователя меняют состояние в `app-store.js` (тиры «Просмотрено/Запланировано», прогресс серий, свои карточки, настройки), сохраняются в `localStorage`/IndexedDB по типу данных, после чего вызывается рендер.
3. **Уведомления/премьеры:** контроллеры запрашивают актуальные события, кэшируют данные и отрисовывают экраны. Ежедневная синхронизация планируется приложением; браузер/Android WebView не гарантируют фон при закрытом приложении.
4. **Постеры:** `app-ctrl-posters.js` ставит загрузку/сжатие в очередь и сохраняет копии в IndexedDB; рендер использует кешированные постеры, когда они доступны.

## Хранилища

### localStorage

| Ключ | Назначение |
|---|---|
| `anitier.v1` | Основное сохранение: списки, прогресс, свои карточки (включая миниатюры/ссылки по принятой схеме), настройки, служебные поля. Версия схемы — `SCHEMA_VERSION = 1`. |
| `anitier.moments.v1` | Метаданные моментов. |
| `anitier.translations.v1` | Кэш переводов. |

Схему менять только обратно совместимо: старые сохранения пользователя не должны ломаться.

### IndexedDB

База: `anitier-media` (версия 3). Хранилища:

| Store | Назначение |
|---|---|
| `images` | Изображения (например, пользовательские/служебные). |
| `media` | Медиа моментов (видео/GIF). |
| `posters` | Кэш постеров. |
| `titles` | Кэш/данные названий (по фактическому использованию store/API). |

Полные постеры и медиа моментов лежат в IndexedDB и в обычную JSON-копию не входят.

## Обмен тир-листами

Обмен реализован в `core.js` и UI-модулях обмена (`app-render-exchange.js` + обработчики). Код экспорта — компактная строка с префиксом `ANITIER-TIER-*` (актуальные константы/формат — в `core.js`: `SHARE_PREFIX`, `SHARE_KIND`, `SHARE_VERSION`, `encodeTierShare`/`makeTierShare`/`parseTierShare`/`compareTierLists`). Импорт показывает сравнение и не меняет пользовательские тиры без явного действия.

## Резервные копии

Резервная копия — JSON-файл (см. `BACKUP_*` и разбор в `core.js`, сборка/применение в `app-store.js`/`app-ctrl-backup.js`). В копию входят списки, прогресс, свои карточки, моменты (метаданные), настройки и данные, предусмотренные схемой копии. Медиаархив и полные медиафайлы обрабатываются отдельно от обычной JSON-копии.

Способы переноса: файл через браузер/системный диалог Android; на сайте и в PWA доступен Google Drive (`app-api.js`), в APK используется файловая копия через Android. Google-авто-бэкап управляется настройками и контроллером резервных копий.

## Диагностика и качество

- Локальная диагностика (`app-ctrl-diagnostics.js`) собирает ошибки/запросы на устройстве и не отправляет данные наружу.
- Тесты: `test.ps1` (headless Edge/Chrome, порт 8099) — функциональные тесты и визуальная регрессия; сценарии в `tests/`. `tests/shell.test.js`/`tests/split.test.js` фиксируют состав и порядок модулей.
- CI: `.github/workflows/tests.yml` запускает `test.ps1 -SkipVisual` на `windows-latest` при push в `main` и PR. Визуальная регрессия остаётся локальной: её эталоны зависят от браузера и шрифтов.
