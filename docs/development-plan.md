# План разработки AniTier

Этот файл — очередь работ. В начале каждой сессии открой его и выполни **первый по порядку** пункт. После выполнения удали пункт целиком. **Номера не меняй и не перенумеровывай**: пропуски означают уже выполненные пункты. Новые пункты добавляй только в конец, со следующим свободным номером.

Если пункт слишком большой, разбей его на подпункты `12.1`, `12.2` — номер верхнего уровня при этом не меняется. Если пункт оказался неверным, не удаляй его молча: замени текст на решение и коротко объясни причину.

## Правила работы

- Язык продукта, коммитов и этого плана — русский.
- Без новых зависимостей и сборщиков. Только HTML/CSS/JS и существующие PowerShell-скрипты.
- Каждый багфикс и каждая новая чистая функция — с тестом в `tests/`.
- После правок: `powershell -ExecutionPolicy Bypass -File .\test.ps1`.
- Если менялись `index.html`, `mobile/`, `*.js` интерфейса или `styles.css` — пересобрать `AniTier-phone.html` и `AniTier.apk` (`build-phone.ps1`, затем `android/build-apk.ps1`).
- Один пункт — один законченный коммит. Сообщение по-русски, в императиве.
- Перед удалением пункта проверь, что тесты зелёные, а критерий готовности выполнен.

## Пункты

### 17. P2 — Разделить `app.js` и `app-render.js`

Файлы: `app.js`, `app-render.js`, `build-phone.ps1`, `mobile/index.html`, `index.html`, `tests/index.html`.

Вынести контроллеры каталога, уведомлений, премьер, бэкапа, моментов и настройки в отдельные файлы; рендер карточек, списков, модалок и экранов — в отдельные. Порядок загрузки зафиксировать в сборке и тестах.

Готово, когда: каждый файл отвечает за одну область, порядок загрузки проверяется тестом, поведение не меняется.

### 18. P2 — Реестр действий вместо switch

Файлы: `app.js`.

Switch на ~700 строк заменить картой `action → handler`, сохранив делегирование и все текущие действия. Неизвестное действие — `console.warn` в тестовом режиме.

Готово, когда: все `data-action` обрабатываются, тесты UI зелёные, добавить новое действие проще одной строкой.

### 19. P2 — Слой сохранения и миграции схемы

Файлы: `app-store.js`.

`SCHEMA_VERSION` пишется, но не используется. Добавить `migrateState(raw)`, debounce записи, обработку quota и явное сообщение, если сохранить не удалось. Старые сохранения должны читаться без потерь.

Готово, когда: есть тест на миграцию со старой версии, запись не блокирует UI на каждое действие, ошибка quota видна пользователю.

### 20. P1 — Миниатюры в IndexedDB

Файлы: `app-store.js`, `app.js`, `app-render.js`.

Миниатюры своих карточек и моментов лежат в localStorage (до ~450 КБ каждая), что грозит переполнением. Хранить их в IndexedDB (`images`/`media`), в localStorage — только ключ. Предусмотреть миграцию старых data URL.

Готово, когда: 100 карточек и 24 момента не превышают лимит localStorage; старые данные переносятся; есть тест миграции.

### 21. P2 — Кнопка «Очистить кэш» и индикатор хранилища

Файлы: `app-render.js` (настройки), `app.js`, `app-api.js`.

Показать занятое место (`navigator.storage.estimate()`), кэш API и постеров, кнопку очистки с подтверждением. Не удалять списки и прогресс.

Готово, когда: пользователь видит, сколько занято, и может очистить кэш без потери данных; есть тест.

### 22. P2 — Убрать inline-обработчики и добавить CSP

Файлы: `app-render.js`, `index.html`, `mobile/index.html`.

`onload="cachePoster(this)"` и `onerror="posterFallback(this)"` мешают строгому CSP. Перейти на делегированные обработчики `load`/`error` или `IntersectionObserver`, добавить CSP-мета с разрешёнными источниками (AniList, Kitsu, Google Fonts, Google Identity, Wikidata, MyMemory, Google Translate).

Готово, когда: CSP не ломает приложение и APK; нет inline-обработчиков; есть тест/ручной сценарий.

### 23. P2 — Безопасность Android WebView

Файлы: `android/src/com/anitier/phone/MainActivity.java`, `android/AndroidManifest.xml`.

`allowUniversalAccessFromFileURLs(true)` и `allowFileAccessFromFileURLs(true)` ослабляют защиту. Перейти на `WebViewAssetLoader` с `https://appassets.androidplatform.net`, выключить universal access, проверить API, шрифты и file chooser. `ReleaseNotificationBootReceiver` сделать `exported="false"`.

Готово, когда: APK работает без universal access, внешние ссылки по-прежнему открываются в браузере, есть чек-лист ручной проверки.

### 24. P2 — Проверки релиза и артефактов

Файлы: `release.ps1`, `tests/core.test.js`.

`release.ps1` не сверяет версию кэша `mobile/sw.js`; тест проверяет только формат. Добавить сверку версии кэша с `APP_VERSION`, проверку свежести `AniTier-phone.html`/APK и тест совпадения `id`/`data-action` между desktop и mobile разметкой.

Готово, когда: релиз падает при рассинхроне версий и артефактов; есть тесты.

### 25. P2 — Производительность

Файлы: `app-render.js`, `app.js`, `core.js`.

Батчить `saveState` при `ensureEpisodeInfo`, memoize `normalizeTitleKey`/`genreRu`, чистить `state.byId` и `posterCache`, ограничить параллельную загрузку постеров. Замерить до/после на 1000 тайтлов.

Готово, когда: нет заметных фризов при открытии уведомлений и списка на 1000 тайтлов; есть замер.

### 26. P2 — Доступность

Файлы: `app-render.js`, `index.html`, `mobile/index.html`, `styles.css`.

Поправить порядок заголовков (h1 → h3 в сообщениях), сузить `aria-live` до статуса, добавить `aria-busy` на загрузки и `aria-describedby` модалкам. Прогнать Lighthouse и axe.

Готово, когда: Accessibility 100 в Lighthouse на ключевых экранах; нет пропусков заголовков.

### 27. P3 — Единая модель статусов и жанров

Файлы: `core.js`, `app-api.js`, `app-store.js`, `app-render.js`.

`collectSeasons`, `episodeStats` и фильтры зависят от русских строк статуса; Kitsu-теги подменяются жанрами; «Science Fiction» и «Экшен» не матчатся с каноническими жанрами. Ввести коды статусов, нормализацию жанровых синонимов и отдельные теги Kitsu.

Готово, когда: статусы и жанры не зависят от языка; есть тесты на синонимы и Kitsu.

### 28. P3 — Локальная диагностика

Файлы: `app.js`, `app-render.js`.

Добавить локальный журнал ошибок (без отправки наружу), счётчик неудачных запросов и кнопку «Скопировать диагностику» в настройках. Не логировать названия и прогресс без согласия.

Готово, когда: пользователь может прислать диагностику, а приложение не отправляет данные само.

### 29. P3 — Визуальная регрессия

Файлы: `tests/`, `test.ps1`.

Добавить скриншоты ключевых экранов (desktop/mobile, пустые/заполненные состояния) и сравнение с эталоном. Не чаще, чем позволяет headless-браузер.

Готово, когда: изменение вёрстки видно в тестах, а не только глазами.
